# ignore_user `version` + TIMESTAMPTZ + IDENTITY Migration (V003) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable Flyway-managed migration of the production `ignore_user`/`message_log` tables from their legacy JPA-created shape to the purist-DDD target shape by rewriting V001/V002 as legacy baselines, adding V003 forward migration, and configuring Flyway baseline-on-migrate.

**Architecture:** V001/V002 replicate the current production schema exactly (so Flyway can baseline prod at version 2). V003 performs the forward changes: adds `ignore_user.version`, converts `ignore_user.created_at`/`updated_at` to `TIMESTAMPTZ` (interpreting naive timestamps as KST), and converts both tables' `id` columns to `GENERATED BY DEFAULT AS IDENTITY`. Fresh environments reach the same final state via V1 → V2 → V3; production skips V1/V2 via baseline and runs V3 only.

**Tech Stack:** PostgreSQL 17, Flyway 11, jOOQ 3.20 (DDLDatabase codegen), Testcontainers, JUnit 5, Gradle 9, Spring Boot 4

**Design Spec:** `docs/superpowers/specs/2026-04-15-ignore-user-version-migration-design.md`

- [ ] **Step 4: Create V003 forward migration**

Create `korConverter/hexagonal/adapter/adapter-persistence/src/main/resources/db/migration/V003__add_version_timestamptz_and_identity.sql` with:

```sql
-- V003: forward migration from legacy JPA schema to purist-DDD target
--   ignore_user: add version (optimistic lock), migrate timestamps to TIMESTAMPTZ
--                (interpreting naive values as Asia/Seoul wall-clock per deploy TZ),
--                convert id to IDENTITY.
--   message_log: convert id to IDENTITY.
-- Rest of message_log alignment is deferred to stage 2/3 per spec.

-- ======================
-- ignore_user
-- ======================

-- 1) Optimistic lock column (rule AD-7)
ALTER TABLE ignore_user
    ADD COLUMN version BIGINT NOT NULL DEFAULT 0;

-- 2) TIMESTAMPTZ conversion.
--    Existing naive timestamps were written by the old JPA BaseTimeEntity using
--    LocalDateTime.now(ZoneId.systemDefault()) on a container with TZ=Asia/Seoul
--    (deploy/docker-compose.yml), so they are KST wall-clock values.
--    'AT TIME ZONE Asia/Seoul' re-interprets them as KST and produces the
--    correct UTC instant.
ALTER TABLE ignore_user
    ALTER COLUMN created_at TYPE TIMESTAMPTZ
        USING created_at AT TIME ZONE 'Asia/Seoul',
    ALTER COLUMN created_at SET DEFAULT now(),
    ALTER COLUMN updated_at TYPE TIMESTAMPTZ
        USING updated_at AT TIME ZONE 'Asia/Seoul',
    ALTER COLUMN updated_at SET DEFAULT now();

-- 3) id IDENTITY conversion. BY DEFAULT accepts explicit values
--    (reconstitute path) and auto-generates when unspecified.
ALTER TABLE ignore_user
    ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;

-- Advance the identity sequence past any existing row ids so auto-generation
-- never collides with legacy rows (setval with `true` makes the *next* call
-- to nextval return max+1).
SELECT setval(
    pg_get_serial_sequence('ignore_user', 'id'),
    COALESCE((SELECT MAX(id) FROM ignore_user), 1),
    true
);

-- ======================
-- message_log
-- ======================

-- 4) id IDENTITY conversion. Deployment blocker: every message conversion
--    calls MessageLogRecordAdapter.record(), which inserts without id.
ALTER TABLE message_log
    ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;

SELECT setval(
    pg_get_serial_sequence('message_log', 'id'),
    COALESCE((SELECT MAX(id) FROM message_log), 1),
    true
);
```

- [ ] **Step 1: Write the failing test**

Create the test file with:

```java
package org.specter.converter.adapter.persistence.migration;

import static org.assertj.core.api.Assertions.assertThat;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.Statement;
import java.time.Instant;
import org.flywaydb.core.Flyway;
import org.junit.jupiter.api.AfterAll;
import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.TestInstance;
import org.testcontainers.containers.PostgreSQLContainer;

@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class LegacyToTargetV003MigrationIT {

  private static final PostgreSQLContainer<?> PG =
      new PostgreSQLContainer<>("postgres:17-alpine");

  @BeforeAll
  void startContainer() {
    PG.start();
  }

  @AfterAll
  void stopContainer() {
    PG.stop();
  }

  @Test
  void migrates_legacy_ignore_user_to_target_with_kst_interpretation() throws Exception {
    // --- 1. Migrate to V2 only ---
    Flyway.configure()
        .dataSource(PG.getJdbcUrl(), PG.getUsername(), PG.getPassword())
        .locations("classpath:db/migration")
        .target("2")
        .load()
        .migrate();

    // --- 2. Insert legacy-shaped rows via raw JDBC ---
    // ignore_user: KST wall-clock 2025-12-31 23:00:00 → expected UTC 14:00:00
    // message_log: just check auto-id after V3
    try (Connection conn = DriverManager.getConnection(
            PG.getJdbcUrl(), PG.getUsername(), PG.getPassword());
        Statement stmt = conn.createStatement()) {
      stmt.executeUpdate(
          "INSERT INTO ignore_user (id, user_id, channel_id, name, created_at, updated_at) "
              + "VALUES (100, 111, 222, 'legacy-user', "
              + "TIMESTAMP '2025-12-31 23:00:00', TIMESTAMP '2025-12-31 23:00:00')");
      stmt.executeUpdate(
          "INSERT INTO message_log (id, guild, channel, nick_name, effective_name, message, "
              + "is_converted, converted_message, channel_id) "
              + "VALUES (200, 'g', 'c', 'nk', 'ef', 'dkssud', true, '안녕', 333)");
    }

    // --- 3. Migrate to V3 ---
    Flyway.configure()
        .dataSource(PG.getJdbcUrl(), PG.getUsername(), PG.getPassword())
        .locations("classpath:db/migration")
        .target("3")
        .load()
        .migrate();

    // --- 4. Assert migration effects ---
    try (Connection conn = DriverManager.getConnection(
            PG.getJdbcUrl(), PG.getUsername(), PG.getPassword());
        Statement stmt = conn.createStatement()) {

      // 4a. ignore_user: version column is 0, timestamps converted to UTC
      try (ResultSet rs = stmt.executeQuery(
          "SELECT version, created_at, updated_at FROM ignore_user WHERE id = 100")) {
        assertThat(rs.next()).isTrue();
        assertThat(rs.getLong("version")).isZero();
        Instant createdAt = rs.getTimestamp("created_at").toInstant();
        Instant updatedAt = rs.getTimestamp("updated_at").toInstant();
        // 2025-12-31 23:00:00 KST == 2025-12-31 14:00:00 UTC
        assertThat(createdAt).isEqualTo(Instant.parse("2025-12-31T14:00:00Z"));
        assertThat(updatedAt).isEqualTo(Instant.parse("2025-12-31T14:00:00Z"));
      }

      // 4b. ignore_user: auto-id works on new INSERT without id
      stmt.executeUpdate(
          "INSERT INTO ignore_user (user_id, channel_id, name, created_at, updated_at) "
              + "VALUES (999, 888, 'auto', now(), now())");
      try (ResultSet rs = stmt.executeQuery(
          "SELECT id FROM ignore_user WHERE user_id = 999")) {
        assertThat(rs.next()).isTrue();
        long autoId = rs.getLong("id");
        assertThat(autoId).isGreaterThan(100L);
      }

      // 4c. message_log: auto-id works on new INSERT without id
      stmt.executeUpdate(
          "INSERT INTO message_log (guild, channel, nick_name, effective_name, message, "
              + "is_converted, converted_message, channel_id) "
              + "VALUES ('g2', 'c2', 'nk2', 'ef2', 'hi', false, null, 444)");
      try (ResultSet rs = stmt.executeQuery(
          "SELECT id FROM message_log WHERE channel_id = 444")) {
        assertThat(rs.next()).isTrue();
        long autoId = rs.getLong("id");
        assertThat(autoId).isGreaterThan(200L);
      }
    }
  }
}
```

Why this file is in a `migration` sub-package: it is a migration regression test, not a port/adapter test. Keeping it separate from `port/` makes the intent clear and avoids it being swept up by port-focused test configurations.

Why raw JDBC instead of jOOQ DSL: jOOQ generated types reflect the FINAL schema (post-V3), but at step 2 the DB is still in post-V2 state (no `version` column, `timestamp` not `timestamptz`). Using jOOQ against the intermediate state would fail. Raw JDBC works at all stages.

Why `.getTimestamp(..).toInstant()`: PostgreSQL JDBC driver returns `Timestamp` whose `toInstant()` gives the absolute UTC moment. The wall-clock KST input 2025-12-31 23:00 becomes Instant 2025-12-31T14:00:00Z after `AT TIME ZONE 'Asia/Seoul'`.

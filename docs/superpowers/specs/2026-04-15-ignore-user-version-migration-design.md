# ignore_user `version`·TIMESTAMPTZ 도입 + id IDENTITY 전환 (V003) 설계

- **날짜**: 2026-04-15
- **상태**: Draft
- **관련 브랜치**: `feature/purist-ddd-migration`
- **관련 커밋**: `2888bf1` (JPA → Flyway + jOOQ 전환, V001/V002 최초 작성), `2f09b53` (purist-DDD 모듈 재구성)
- **관련 ADR**: ADR-0001 (BIGSERIAL id strategy), ADR-0002 (jOOQ generated code location)
- **관련 규칙**: AD-7 (Optimistic Lock), CLAUDE.md (Flyway manages DDL migrations)

## 1. 배경

운영 DB의 `ignore_user` 테이블은 삭제된 JPA 어댑터(`IgnoreUserEntity` + `BaseTimeEntity`) 시절에 생성된 **legacy 스키마**다. 현재 `feature/purist-ddd-migration` 브랜치에서 Flyway V001/V002(target schema)를 추가했지만 운영 DB에는 아직 한 번도 적용된 적이 없고, `flyway_schema_history` 테이블도 존재하지 않는다.

### 1.1 운영 DB 현재 상태 (`ignore_user`)

```sql
CREATE TABLE public.ignore_user (
  id          bigint                         NOT NULL,
  created_at  timestamp(6) without time zone NOT NULL,
  updated_at  timestamp(6) without time zone NOT NULL,
  channel_id  bigint                         NOT NULL,
  name        varchar(255),
  user_id     bigint                         NOT NULL,
  CONSTRAINT ignore_user_pkey PRIMARY KEY (id)
);
CREATE INDEX idx_ignore_user_user_id ON public.ignore_user (user_id, channel_id);
```

### 1.2 V001 목표 스키마 (현재 저장소)

```sql
CREATE TABLE ignore_user (
    id          BIGSERIAL    PRIMARY KEY,
    user_id     BIGINT       NOT NULL,
    channel_id  BIGINT       NOT NULL,
    name        VARCHAR(255),
    version     BIGINT       NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_ignore_user_lookup ON ignore_user (user_id, channel_id);
```

### 1.3 차이 원인 분석

| 항목 | 차이 | 원인 | 성격 |
|------|------|------|------|
| `version` 컬럼 | 없음 → 추가 | 규칙 AD-7(Optimistic Lock) 신규 도입 | **배포 블로커** — 어댑터가 `WHERE version = ?`로 UPDATE |
| `created_at`/`updated_at` 타입 | `timestamp` → `TIMESTAMPTZ` | 삭제된 `BaseTimeEntity`가 `LocalDateTime`(Hibernate 기본: `timestamp`)을 사용. purist-DDD 도메인은 `Instant`(UTC 절대시각) 사용 | **배포 블로커** — 어댑터 코드가 `OffsetDateTime.ofInstant(..., UTC)`로 하드코딩되어 `timestamp`이면 jOOQ 타입 매핑 불일치 |
| `ignore_user.id` 생성 전략 | `BIGINT` (Hibernate 시퀀스) → 자동 증가 (IDENTITY) | 옛 JPA는 `@GeneratedValue(strategy=SEQUENCE)`로 `hibernate_sequence` 공용 시퀀스 사용. 어댑터는 INSERT 시 id를 지정하지 않고 DB 자동 발급 전제 | **배포 블로커** — `IgnoreUserPersistenceAdapter.save()`가 `.set(IGNORE_USER.ID, ...)` 미호출. V003에서 `GENERATED BY DEFAULT AS IDENTITY`로 해소 |
| `message_log.id` 생성 전략 | 동일 | 동일 | **배포 블로커** — `MessageLogRecordAdapter.record()`도 `.set(MESSAGE_LOG.ID, ...)` 미호출. 모든 메시지 변환 경로가 이를 호출하므로 미해결 시 **봇 전체 기능 다운**. V003 동일 방식으로 해소 |
| `message_log.message` 등 `varchar(255)` | → `TEXT` | Discord 메시지 최대 2000자 + 링크 → 데이터 잘림 리스크 제거 | **후속 단계 2** |
| `message_log.updated_at` | 있음 → 제거 | `BaseTimeEntity` 상속 산물. append-only 로그에 무의미 | **후속 단계 3** |
| 인덱스명 `idx_ignore_user_user_id` | → `idx_ignore_user_lookup` | JPA 어노테이션 생성명 → 의미 기반 네이밍 | **후속 단계 3** |
| `message_log.channel_id DEFAULT 0` | → nullable | JPA `@ColumnDefault("0")` 산물 | **후속 단계 2** |

> 중요: **jOOQ가 지원하지 않아서 바뀐 항목은 하나도 없다.** jOOQ는 `timestamp without time zone`, `varchar(255)`, 수동 시퀀스를 모두 지원한다. 모든 차이는 JPA → jOOQ 전환 커밋(`2888bf1`)에서 동시에 수행된 **의도적 개선**이다.

## 2. 목표

- 운영 DB의 `ignore_user` 테이블에 `version` 컬럼을 추가하여 규칙 AD-7(Optimistic Lock)을 만족시킨다.
- `ignore_user.created_at`/`updated_at`을 `TIMESTAMPTZ`로 전환하여 도메인 `Instant` 모델과 정합시킨다.
- 두 테이블(`ignore_user`, `message_log`)의 `id` 컬럼을 자동 발급(IDENTITY) 가능하게 하여 어댑터 INSERT를 복구한다.
- Flyway를 운영 DB의 1차 도입 수단으로 하여, 이후 모든 DDL 변경이 Flyway 이력에 기록되도록 한다.
- `message_log`의 나머지 정렬(타입 확대, `updated_at` 제거, TIMESTAMPTZ 전환) 및 레거시 시퀀스/인덱스 정리는 **후속 단계**로 분리하고 본 스펙에 로드맵만 명시한다.

## 3. 비목표 (YAGNI)

- `message_log` 컬럼 타입(`TEXT` 확대), `updated_at` 제거, `channel_id` 기본값 제거 등 정렬 — 단계 2/3
- `hibernate_sequence` 등 레거시 시퀀스 정리 — 단계 3
- 인덱스명 `idx_ignore_user_user_id` → `idx_ignore_user_lookup` 개명 — 단계 3
- Flyway undo 마이그레이션 작성 — Flyway 유료 기능 미도입
- 운영 무중단 배포 (zero-downtime) 설계 — Discord 봇 재시작 수십 초 허용

## 4. 결정

### 4.1 전략: "V001/V002 재작성(legacy baseline) + V003 forward"

V001은 아직 어느 환경에도 적용된 적이 없으므로 rewrite 가능하다(Flyway 사전 릴리스). 운영 DB의 현재 모습을 V001/V002에 정확히 복제하여 Flyway가 해당 DB 역사의 충실한 기록이 되게 한다.

**동작:**
- **운영** (tables 존재, history 없음) → `baseline-on-migrate=true` + `baseline-version=2`로 V1/V2 스킵 → V3 실행 → 타깃 스키마 도달
- **Fresh env** (Testcontainers, empty DB) → V1/V2/V3 순차 실행 → 동일 타깃 스키마 도달

### 4.2 대안 비교

| 후보 | 판정 | 근거 |
|------|------|------|
| V001/V002 재작성 + V003 forward (채택) | ✅ | 각 마이그레이션이 단순/결정적. Flyway가 DB 역사의 충실한 기록. V001 사전 릴리스 상태 |
| V001/V002 유지 + idempotent V003 | ❌ | V003 SQL이 `ADD COLUMN IF NOT EXISTS`, 조건부 DO 블록으로 복잡해짐. 멱등성을 수동으로 보장해야 해서 실수 여지 |
| Flyway 바이패스 + 수동 SQL 배포 | ❌ | CLAUDE.md "Flyway manages DDL migrations" 규칙 위반. 환경 재현 불가, 롤백 흔적 없음 |

### 4.5 V003 forward (본 스펙의 본체)

```sql
-- V003__add_version_timestamptz_and_identity.sql
-- Purpose:
--   1) ignore_user: optimistic lock (version) + TIMESTAMPTZ + id IDENTITY
--   2) message_log: id IDENTITY (nothing else — rest deferred to stage 2/3)
-- 배포 블로커: 두 어댑터 모두 INSERT 시 id를 지정하지 않음 → DB auto-gen 필수

-- ======================
-- ignore_user
-- ======================

-- 1) optimistic lock 컬럼
ALTER TABLE ignore_user
    ADD COLUMN version BIGINT NOT NULL DEFAULT 0;

-- 2) TIMESTAMPTZ 전환 (컨테이너 TZ=Asia/Seoul 전제; deploy/docker-compose.yml 근거)
--    기존 naive timestamp = KST 벽시계 → AT TIME ZONE 'Asia/Seoul'로 UTC 승격
ALTER TABLE ignore_user
    ALTER COLUMN created_at TYPE TIMESTAMPTZ
        USING created_at AT TIME ZONE 'Asia/Seoul',
    ALTER COLUMN created_at SET DEFAULT now(),
    ALTER COLUMN updated_at TYPE TIMESTAMPTZ
        USING updated_at AT TIME ZONE 'Asia/Seoul',
    ALTER COLUMN updated_at SET DEFAULT now();

-- 3) id IDENTITY 전환 (배포 블로커 해소)
--    BY DEFAULT: 명시 값 허용(reconstitute 경로 대비), 미지정 시 자동 발급
ALTER TABLE ignore_user
    ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;

SELECT setval(
    pg_get_serial_sequence('ignore_user', 'id'),
    COALESCE((SELECT MAX(id) FROM ignore_user), 1),
    true
);

-- ======================
-- message_log
-- ======================

-- 4) id IDENTITY 전환 (배포 블로커 해소 — 모든 메시지 변환 경로 의존)
ALTER TABLE message_log
    ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;

SELECT setval(
    pg_get_serial_sequence('message_log', 'id'),
    COALESCE((SELECT MAX(id) FROM message_log), 1),
    true
);
```

### 4.6 Flyway 설정

`runtime/cfg/application.yml`의 `spring.flyway` 블록을 다음과 같이 확장(기존 `enabled: true`, `locations: classpath:db/migration` 유지):

```yaml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
    baseline-version: 2
    baseline-description: "legacy JPA schema snapshot"
    # validate-on-migrate: true  (default; V001/V002 체크섬 검증)
```

**동작 사양:**
- 운영(tables 존재, history 없음) → `flyway_schema_history`에 V2 baseline row 삽입 → V1/V2 스킵 → V3 실행
- Fresh env(empty DB, history 없음) → baseline 조건 불성립 → V1/V2/V3 순차 실행

### 4.7 jOOQ codegen 영향

- `DDLDatabase`는 V001 → V002 → V003 순차 적용된 **최종 스키마**로 codegen
- 최종 스키마가 현재 V001 목표와 동치이므로 generated 코드(`IgnoreUser`, `MessageLog` 테이블 바인딩)는 **변동 없음** 또는 순서 차이 수준
- `./gradlew :adapter-persistence:generateJooq` 실행 후 diff 검증 필요

### 4.8 어댑터 코드 영향

| 파일 | 변경 여부 | 근거 |
|------|-----------|------|
| `IgnoreUserPersistenceAdapter` | **변경 없음** | 최종 스키마가 현재 V001 타깃과 동치(`version BIGINT`, `TIMESTAMPTZ`) |
| `IgnoreUserQueryAdapter` | **변경 없음** | `version` / timestamp 참조 없음 |
| `MessageLogRecordAdapter` | **변경 없음** | V003 이후 `id` auto-id 확보. V002 재작성의 `updated_at DEFAULT now()`로 insert 시 생략 가능 |
| 기존 테스트(어댑터/E2E) | **변경 없음 예상** | `IgnoreUser.create()` → `IgnoreUserId.UNSAVED` → INSERT auto-id로 동작 |

## 5. 후속 단계 로드맵

### 단계 2 — `message_log` 목표 정렬

- `message_log.message` / `converted_message`를 `TEXT`로 확대 (Discord 2000자 대응)
- `message_log.channel_id DEFAULT 0` 제거
- `message_log.created_at`/`updated_at` `TIMESTAMPTZ` 전환
- (`id` IDENTITY는 V003에서 이미 처리 완료)
- 별도 ADR 없음, 스펙만 추가

### 단계 3 — 레거시 정리

- `message_log.updated_at` 제거 (append-only 로그)
- `hibernate_sequence` (존재 시) DROP
- 인덱스 `idx_ignore_user_user_id` → `idx_ignore_user_lookup` 개명
- 별도 스펙 작성

## 6. 롤백 전략

| 시나리오 | 대응 |
|----------|------|
| V003 실행 중 실패 | Flyway 파일 단위 TX → 전체 롤백. 운영 상태 무변화 |
| V003 적용 후 어댑터 레벨 버그 발견 | 아래 수동 역마이그레이션 SQL + `flyway_schema_history` V3 row 삭제 |
| 타임존 변환 오해석으로 데이터 shift 발견 | 백업 복원 (TIMESTAMPTZ는 KST 변환된 UTC만 보존; 역변환 가능하나 무의미한 shift 발견 시 복원이 안전) |

**수동 역마이그레이션 SQL** (runbook only, 저장소 비커밋):

```sql
ALTER TABLE message_log ALTER COLUMN id DROP IDENTITY IF EXISTS;
ALTER TABLE ignore_user ALTER COLUMN id DROP IDENTITY IF EXISTS;
ALTER TABLE ignore_user
    ALTER COLUMN updated_at DROP DEFAULT,
    ALTER COLUMN updated_at TYPE TIMESTAMP(6) WITHOUT TIME ZONE
        USING updated_at AT TIME ZONE 'Asia/Seoul',
    ALTER COLUMN created_at DROP DEFAULT,
    ALTER COLUMN created_at TYPE TIMESTAMP(6) WITHOUT TIME ZONE
        USING created_at AT TIME ZONE 'Asia/Seoul';
ALTER TABLE ignore_user DROP COLUMN version;
DELETE FROM flyway_schema_history WHERE version = '3';
```

### 7.1 신규 테스트 핵심 (`LegacyToTargetV003MigrationIT`)

```
1. Testcontainers Postgres 기동
2. Flyway.configure().target("2").load().migrate()  — V1/V2까지만
3. raw SQL로 KST wall-clock timestamp 가진 ignore_user row 삽입
   (id 명시, timestamp 값은 2025-12-31 23:00:00 KST 등)
4. raw SQL로 message_log row 삽입 (id 명시)
5. Flyway.configure().target("3").load().migrate()  — V3 실행
6. jOOQ DSLContext로 재조회
7. Assert:
   - ignore_user: version == 0
   - ignore_user: created_at.toInstant() == Instant.parse("2025-12-31T14:00:00Z")
     (즉 KST − 9h)
   - ignore_user: INSERT without id → 새 row auto-id 발급
   - message_log: INSERT without id → 새 row auto-id 발급
```
